> 这份文档把整个项目从头到尾、一个文件一个文件讲清楚。适合你理解自己的代码，也适合面试/答辩时照着讲。

## 一、这个项目是干什么的

一个**家庭园艺与种植智能顾问**，底层是一个 **ReAct Agent**（能自己思考、自己调用工具的 AI 助手），具备三大能力：

1. **专业问答（RAG）**：从本地知识库（`data/` 下的 txt 文件）检索蔬菜/果树/花卉的种植习性、水肥管理、病虫害防治、修剪繁殖等资料；
2. **天气适配**：调用 Open-Meteo 免费 API 查真实天气，判断浇水/施肥/打药/防冻/遮阴等操作是否适宜；
3. **用户 + 种植日志 + 报告**：用户注册登录，口述种植数据可保存，能生成个人月度种植报告。

界面用 **Streamlit** 做，模型用 **DeepSeek**，向量化用 **阿里云百炼 text-embedding-v3**，向量库用 **Chroma**，持久化用 **SQLite**。

## 二、整体架构与数据流

```
用户浏览器 (Streamlit app.py)
        │  提问
        ▼
ReactAgent (agent/react_agent.py)
        │  system_prompt + 7 个工具 + 3 个中间件
        ▼
DeepSeek 大模型 (model/factory.py)
        │  模型决定「要不要调工具、调哪个」
        ▼
工具层 (agent/tools/agent_tools.py)
   ├── rag_summarize      → 向量库检索 (rag/vector_store.py → Chroma) → 总结 (rag/rag_service.py)
   ├── get_weather        → Open-Meteo API (weather_tool.py)
   ├── get_user_id        → 从会话上下文读当前登录用户
   ├── get_current_month  → 系统当前月份
   ├── fetch_external_data→ 读 SQLite 记录 (utils/storage.py)
   ├── save_record        → 写 SQLite 记录 (utils/storage.py)
   └── fill_context_for_report → 标记「报告场景」，触发切换提示词
        │  工具结果返回模型，模型整合出最终回答
        ▼
最终回答流式返回给界面
```

**一个具体例子的完整流程**（用户问「我这个月番茄长到 40cm，浇了 10 次水，施了两次有机肥」）：

1. `app.py` 把这句话和登录用户的 `user_id` 一起交给 Agent；
2. 模型看到系统提示词里的「保存提醒规则」，判断用户提供了种植数据；
3. 模型在回答末尾询问「是否需要我帮你保存这份记录？」；
4. 用户回复「保存」→ 模型调用 `save_record` 工具 → 写进 SQLite；
5. 用户再问「生成我的种植报告」→ 模型调 `fill_context_for_report`（触发报告提示词）→ 调 `fetch_external_data` 读库 → 生成报告。

### 3.2 Agent 装配层

#### `agent/react_agent.py` —— 把模型、提示词、工具、中间件组装成 Agent

```python
from langchain.agents import create_agent
from model.factory import chat_model_factory
from utils.prompt_loader import load_system_prompt
from agent.tools.agent_tools import (rag_summarize, get_weather, get_user_id,
                                     get_current_month, fetch_external_data,
                                     fill_context_for_report, save_record)
from agent.tools.middleware import monitor_tool, log_before_model, report_prompt_switch
```

- `create_agent` 是 LangChain 提供的 ReAct Agent 工厂函数，一行就造出一个「会思考会调工具」的 Agent。
- 导入 7 个工具和 3 个中间件。

```python
class ReactAgent:
    def __init__(self):
        self.agent = create_agent(
            model=chat_model_factory.generator(),      # DeepSeek 模型
            system_prompt=load_system_prompt(),        # 主提示词（从 txt 读）
            tools=[
                rag_summarize, get_weather, get_user_id,
                get_current_month, fetch_external_data,
                fill_context_for_report, save_record,   # 共 7 个工具
            ],
            middleware=[
                monitor_tool,          # 监控每次工具调用
                log_before_model,      # 模型调用前打日志
                report_prompt_switch,  # 报告场景动态切换提示词
            ],
        )
```

- `tools`：告诉 Agent「你能调这些工具」。
- `middleware`：三个钩子，分别在「工具调用时」「模型调用前」「提示词选择时」介入（见 3.5 节）。

```python
    def execute_stream(self, messages: list, user_id: str = ""):
        input_dict = {'messages': messages}
        for chunk in self.agent.stream(input_dict, stream_mode="values",
                                       context={'report': False, 'user_id': user_id}):
            latest_message = chunk['messages'][-1]
            text = _extract_text(latest_message.content)
            if text:
                yield text.strip() + "\n"
```

- `context={'report': False, 'user_id': user_id}` 是**运行时上下文**，注入到工具里：
  - `report`：报告场景开关（`fill_context_for_report` 工具会把它改成 True）。
  - `user_id`：当前登录用户，`get_user_id` 和 `save_record` 从这里读。
- `stream(mode="values")` 流式返回每一步，`yield` 逐段吐给界面。
- `_extract_text` 是个兼容函数：模型输出的 `content` 可能是字符串，也可能是 content block 列表，这里统一提取纯文本。

### 3.4 RAG 层（检索增强生成）

#### `rag/vector_store.py` —— 向量库：把知识文件切块、向量化、存进 Chroma

```python
class VectorStoreService:
    def __init__(self):
        self.vector_store = Chroma(
            collection_name=chroma_conf['collection_name'],   # "agent"
            persist_directory=get_abs_path(chroma_conf['persist_directory']),  # chroma_db/
            embedding_function=embedding_factory.generator()   # 向量化函数
        )
        self.spliter = RecursiveCharacterTextSplitter(
            chunk_size=chroma_conf['chunk_size'],       # 200 字一块
            chunk_overlap=chroma_conf['chunk_overlap'], # 块之间重叠 20 字
            separators=chroma_conf['separators'],       # 按 "\n\n"、"\n"、"。" 切
            length_function=len,
        )
```

- `Chroma` 是向量数据库，负责存「文字 → 向量」的对应关系。
- `RecursiveCharacterTextSplitter` 把长文档切成小块（200 字），这样检索更精准。

```python
    def get_retriever(self):
        return self.vector_store.as_retriever(search_kwargs={"k": chroma_conf['k']})  # 每次取最相关的 3 块
```

- `as_retriever` 返回一个「检索器」，输入问题能返回最相关的 3 块文字。

```python
    def load_documents(self, documents):
        # 三个内嵌函数：
        #   check_md5_hex(md5)  —— 检查这个文件的 MD5 是否已经入库过
        #   save_md5_hex(md5)   —— 把 MD5 记录到 md5.text 文件
        #   get_file_documents  —— 按后缀选 pdf_loader 或 text_loader
        allowed_files_path = listdir_with_allowed_type(
            get_abs_path(chroma_conf['data_path']),        # data/ 目录
            tuple(chroma_conf['allow_knowledge_file_type']) # 只认 pdf、txt
        )
        for path in allowed_files_path:
            md5_hex = get_file_md5_hex(path)
            if check_md5_hex(md5_hex):      # 已入库 → 跳过（避免重复入库）
                continue
            documents = get_file_documents(path)      # 读文件
            split_documents = self.spliter.split_documents(documents)  # 切块
            self.vector_store.add_documents(split_documents)  # 入库
            save_md5_hex(md5_hex)           # 记录 MD5
```

- **MD5 去重机制**：用文件 MD5 值判断「这个文件是否已经导入过向量库」，避免每次启动重复导入。
- 注意：`load_documents` 目前没有在 `app.py` 或 `react_agent.py` 里被主动调用——它是把知识库导入向量库的工具函数（需要手动/首次运行时触发导入）。

#### `rag/rag_service.py` —— RAG 总结：检索 + 交给模型总结

```python
class RagSummarizeService(object):
    def __init__(self):
        self.vector_store = VectorStoreService()
        self.retriever = self.vector_store.get_retriever()
        self.prompt_text = load_rag_prompt()              # 读 prompt/rag_summarize.txt
        self.prompt_template = PromptTemplate.from_template(self.prompt_text)
        self.model = chat_model_factory.generator()
        self.chain = self._init_chain()

    def _init_chain(self):
        chain = self.prompt_template | print_prompt | self.model | StrOutputParser()
        return chain
```

- 用 LangChain 的 **LCEL（链式表达式）** 把「提示词 → 打印 → 模型 → 字符串解析」串成一条链。`|` 就是「把上一个的输出传给下一个」。

```python
    def rag_summarize(self, query: str) -> str:
        context_docs = self.retriever.invoke(query)   # 检索最相关的 3 块
        context = ""
        for i, doc in enumerate(context_docs, 1):
            context += f"【参考资料{i}】: {doc.page_content} | {doc.metadata}\n"
        return self.chain.invoke({"input": query, "context": context})
```

- 把「用户问题」+「检索到的参考资料」一起交给模型，让模型**基于资料**总结回答（这就是 RAG：先检索、再生成，避免瞎编）。

### 3.5 中间件层

#### `agent/tools/middleware.py` —— 三个钩子，在 Agent 运行过程中拦截

```python
@wrap_tool_call
def monitor_tool(request, handler):
    logger.info(f"工具调用: {request.tool_call['name']}")
    result = handler(request)   # 真正执行工具
    if request.tool_call['name'] == 'fill_context_for_report':
        request.runtime.context['report'] = True   # 标记报告场景
    return result
```

- `@wrap_tool_call`：包裹每次工具调用。每次调工具前先打日志，执行完后如果调的是 `fill_context_for_report`，就把 `context['report']` 置为 `True`（触发报告提示词切换）。
- 出错时捕获异常，返回一条「工具调用失败」消息，不让 Agent 崩溃。

```python
@before_model
def log_before_model(state, runtime):
    logger.info(f"即将调用模型, 带有 {len(state['messages'])} 个外部数据")
    return None
```

- `@before_model`：每次模型调用前打日志，方便调试。

```python
@dynamic_prompt
def report_prompt_switch(request):
    is_report = request.runtime.context.get('report', False)
    if is_report:
        return load_report_prompt()   # 报告场景 → 用报告提示词
    else:
        return load_system_prompt()   # 普通场景 → 用主提示词
```

- `@dynamic_prompt`：**动态切换提示词**。如果 `report` 是 True，就用专门的「报告写手」提示词；否则用主提示词。这是整个项目最巧妙的一处设计。

### 3.6 工具层

#### `agent/tools/agent_tools.py` —— 7 个工具

每个工具用 `@tool` 装饰，`description` 是给模型看的「使用说明书」。

1. **`rag_summarize(query)`**：调 `rag.rag_summarize` 做检索+总结。
2. **`get_weather(city)`**：调 `fetch_weather_by_city` 查天气。
3. **`get_user_id(runtime)`**：从 `runtime.context` 读当前登录用户 ID，未登录返回空串。
4. **`get_current_month()`**：返回系统当前月份，格式 `YYYY-MM`。
5. **`fetch_external_data(user_id, month)`**：读 SQLite 里指定用户指定月份的记录。
6. **`fill_context_for_report()`**：无实际功能，就是「打个标记」，让 `monitor_tool` 捕获后切提示词。
7. **`save_record(growth, care, comparison, month, runtime)`**：把用户口述的种植数据（生长情况、养护管理、长势对比）写进 SQLite。

重点看 3、7 两个「会话工具」：

```python
@tool(description="获取当前登录用户的ID，未登录时返回空字符串")
def get_user_id(runtime: Annotated[ToolRuntime, InjectedToolArg]) -> str:
    ctx = runtime.context or {}
    return ctx.get("user_id", "")
```

- `runtime` 是 **注入参数**（`InjectedToolArg`），不是模型填的，而是框架自动塞进来的。模型**看不到**这个参数，也**不能伪造**——它由 `execute_stream` 的 `context` 决定。

```python
@tool(description="把用户口述的种植数据（生长情况、养护管理、长势对比）保存到该用户的种植日志中；month 为空则存到当前月")
def save_record(growth: str, care: str, comparison: str, month: str = "",
                runtime: Annotated[ToolRuntime, InjectedToolArg] = None) -> str:
    ctx = (runtime.context or {}) if runtime else {}
    user_id = ctx.get("user_id", "")
    if not user_id:
        return "未登录，无法保存记录，请先登录"
    m = month or datetime.now().strftime("%Y-%m")
    storage.save_record(user_id, growth, care, comparison, m)
    return f"已保存用户 {user_id} 在 {m} 的种植日志"
```

- `user_id` 不是模型传入的，而是从会话上下文拿的 → 保证**存到当前登录用户的种植日志下**，模型没法冒充别人。
- 未登录直接返回提示，不写库。

### 3.7 持久层（这次新增的核心）

#### `utils/storage.py` —— SQLite 持久化

这是本次改造新增的核心文件，一条一条看：

```python
DB_PATH = get_abs_path(agent_conf.get('db_path', 'data/app.db'))
```

- 数据库文件路径，从 `config/agent.yml` 的 `db_path` 读（默认 `data/app.db`）。

```python
@contextmanager
def _db():
    conn = sqlite3.connect(DB_PATH)
    conn.row_factory = sqlite3.Row   # 让查询结果可以按列名访问（row['user_id']）
    conn.execute("PRAGMA busy_timeout = 5000")   # 等锁最多 5 秒
    conn.execute("PRAGMA journal_mode = WAL")    # WAL 模式，允许多进程读写并发
    try:
        yield conn
        conn.commit()
    finally:
        conn.close()
```

- `_db()` 是**上下文管理器**，统一管理连接的打开/提交/关闭。所有数据库操作都走它。
- `WAL` + `busy_timeout` 是为了让多个进程同时用这个数据库也不打架。

- 密码直接**明文存储**（演示项目为简化处理，不做加盐哈希）。

```python
def init_db(db_path=None):
    ...建 users 表和 records 表...
    _seed_if_empty()   # 空库时播种 12 个演示用户
```

- `users` 表：`user_id`（如 1001）、`username`、`password`（明文）、`profile`（画像）、`registered_at`。
- `records` 表：`user_id`、`month`、`growth`（生长情况）、`care`（养护管理）、`comparison`（长势对比）、`saved_at`。

```python
def _seed_if_empty():
```

## 四、几个关键概念（面试可能被问）

| 概念 | 一句话解释 | 在项目哪里 |
|---|---|---|
| **ReAct** | 让模型「边思考边行动」：思考→调工具→观察结果→再思考，直到能回答 | `react_agent.py` 的 `create_agent` + 主提示词的思考准则 |
| **RAG** | 先从知识库检索相关资料，再让模型基于资料生成，避免瞎编 | `vector_store.py`（检索）+ `rag_service.py`（总结） |
| **向量数据库** | 把文字转成向量存起来，按「语义相似度」检索（不是关键词匹配） | Chroma，`vector_store.py` |
| **Embedding（向量化）** | 把一句话变成一串数字，意思相近的话数字也相近 | `EmbeddingFactory` |
| **Function Calling / 工具调用** | 模型不直接输出答案，而是输出「我要调 X 工具、参数是 Y」，由程序执行 | `@tool` 装饰的 7 个工具 |
| **上下文注入** | 把「当前用户是谁」这类框架层面的信息悄悄塞给工具，模型无法伪造 | `InjectedToolArg` + `runtime.context` |
| **中间件** | 在 Agent 运行过程中插入钩子，做日志/监控/切提示词 | `middleware.py` 的三个装饰器 |
| **工厂模式** | 用一个「工厂」统一创建对象，换实现只改配置 | `model/factory.py` |
